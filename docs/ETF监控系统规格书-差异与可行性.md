## 一、结论

1. **可行**。规格书需要的字段全部能在现有东方财富链路上拿到，不需要 iFinD / 问财 / Tushare；指数、涨停池接口均返回 `Access-Control-Allow-Origin: *`，纯静态站可直接在浏览器取数。
2. **这不是现有看板的升级，而是另一套策略**。规格书是「档位驱动 + 五条件」，现有看板是「周线 KDJ 凹底 + 17 日线」。两者选股逻辑、指标周期、仓位口径都不同，建议**并列双引擎**，不要互相覆盖。
3. **落地前有 8 项口径必须先定**（见第五节），其中 2 项是规格书内部直接矛盾（煤炭、J 阈值），1 项是未定义（KDJ 周期），不确认就无法写死实现。
4. **标的池会明显收缩**：现有看板展示 770 只（成交额 ≥1000 万），按规格书五条基础筛选后为 **326 只**。
5. 工作量（数据+档位+信号清单，不含仓位与执行）约 **3.5–4 个工作日**。

## 四、规格书内部矛盾与未定义口径

### 4.1 煤炭同时出现在两个互斥名单（矛盾）

- §5.2 防御型名单包含 **煤炭 515220**
- §5.3 防守档黑名单包含 **煤炭**

防守档下「只买防御型」与「煤炭禁买」直接冲突，必须二选一。

### 4.2 中性档 J 阈值自相矛盾（冗余）

§6.1 C4 已定义 `J <= 90`，§6.2 中性档又写 `C4 and J <= 100`。因 C4 已限制 90，`J<=100` 永不生效，
导致**中性档与防守档在 J 上完全一致**，两档只剩「距 MA20 8% vs 6%」与仓位系数不同。若本意是中性档放宽到 100，则 C4 应拆成独立条件。

### 4.3 KDJ 周期未定义（关键）

§3.3 只写公式，未写日线/周线；§6.1 用 `J`。现有博主法用的是**周线 J**，
若规格书是**日线 J**，两者数值完全不同（同一只 ETF 今日 159562：周线 J=11，日线 J 通常几十），不可混用。
这一项决定 C4 与 `J>100 绝对禁买` 的实际效果，必须先确认。

### 4.4 盘中阈值按全天口径写，11:35 必然不达标

- 环境强度要求 `成交额 >= 1.4 万亿`：11:35 只成交约半日（约 0.9 万亿），永远判不出「强」。
- 涨停家数阈值 60/40 同样是全天口径，11:35 尚未涨停完。
→ 需要明确：盘中按时间折算（×1.8 左右）还是沿用上一交易日全天值。

### 4.5 档位判定用「收盘 >= MA20」，盘中无收盘

11:35 扫描时只有实时价。需明确用「实时价 vs 滚动 MA20」还是「上一交易日收盘 vs 前一日 MA20」。
两种口径会在临界日给出不同档位。

### 4.6 「股票型 ETF」是否含跨境（QDII）

跨境 ETF 是股票资产但跟踪境外指数，现有分类单独列为「跨境」共 253 只被排除。
若规格书本意包含（纳指就在防守档黑名单里，说明至少部分跨境是考虑过的），池子会扩大。

### 4.7 规模口径

「规模 ≥10 亿」用份额×市价（东财 f21）还是份额×净值（IOPV）？两者差异通常在 1% 内，
但折算/分红日会跳变，需要固定一种并写明。

### 4.8 资金基数

§10.1 的 600 / 900 / 3000 元反推总资产为 **3 万元**；现有做 T 与定投口径是 2 万 / 单笔 6000。
若本轮不做仓位引擎，这一项可延后；但看板上的「仓位建议」若给出金额，必须先确认基数。

### 4.9 扫描时点 vs 连续刷新

规格书要求 11:35 与 15:05 两个离散时点；现有看板是每 3 分钟连续刷新。
两者不冲突，但需要明确：是否要在 11:35 / 15:05 冻结一份「扫描快照」用于对比与复盘。

## 六、实现方案与成本（P1 + P2：数据 + 档位 + 信号清单）

### 6.1 数据层

- 新增：指数日线（上证、创业板）、全 A 股 21 根收盘摘要（算宽度）、涨停池、ETF 规模。
- 全 A 股宽度在**构建期**算好写进 `base.json` 的 meta（浏览器无法对 5563 只现算）；
  页面标注「宽度为基准日收盘口径」，盘中不刷新。
- 涨停家数、两市成交额、指数实时价可**盘中取**（都是单次请求）。
- 构建耗时：ETF 部分维持 2–3 秒；全 A 股部分新增 **约 3–4 分钟**（仅首次/换日时跑，增量可按日缓存）。缓存摘要约 2MB。

### 6.2 指标层

- Python 与前端 JS 双端实现：MA20、MA20 连升 3 日、MACD、日线 KDJ（若 Q3 定为日线）、距 MA20。
- 沿用现有「双端逐值对齐」校验方式，保证口径一致。

### 6.3 页面层

- 顶部新增**档位条**：档位（进攻/中性/防守）+ 上证/创业板 vs MA20 + 环境（宽/成交额/涨停）。
- 新增策略切换：博主波段法 / 规格书档位引擎。
- 规格书视图的表格列：信号、名称代码、现价、J、距 MA20、MA20 连升、MACD 金叉、板块属性、仓位系数、止损位。
- 可买清单 + 明日预备清单（差哪一项、触发价）。

### 6.4 成本

| 项 | 估算 |
|---|---|
| 数据层 | 1 天 |
| 指标层（双端） | 0.5 天 |
| 档位 + 环境 + 条件矩阵 | 1 天 |
| 页面与清单 | 1–1.5 天 |
| 校验与部署 | 0.5 天 |
| **合计** | **3.5–4 天** |

### 6.5 风险

- 全 A 股宽度依赖 5563 次请求，东财限流时需重试与降级（缺失时页面标「宽度不可用」而不是给默认值）。
- 规格书推荐的 iFinD / 问财 / Tushare 均未采用：问财有 WAF（仓库已有结论），iFinD 需账号，Tushare 需 token；东财免费链路已实测可用。
- 档位与环境是**市场级**判断，一旦算错会整体放大或收缩仓位；建议先只读展示，稳定 2 周后再接仓位。

## 七、建议顺序

1. 先确认 Q1–Q8（尤其 Q3 KDJ 周期、Q1 煤炭、Q4 盘中阈值），这四项不定，信号数量会差一倍以上。
2. 实现数据层 + 指标层，先出「只读信号清单」，不接仓位。
3. 看板并列双引擎，保留现有博主法视图。
4. 观察两周（记录每日档位、信号数、事后 5 日收益），再决定是否接仓位引擎。
